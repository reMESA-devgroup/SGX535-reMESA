# Committed vertex windows and actual index bounds

The next validator follows actual vertex PDS and active u16 index buffers.
It checks committed geometry records rather than treating the rounded GEM
allocation as the vertex count. This is not a shader-body or GPU-execution
certificate.

`vertex_fetch.h` recognizes known fields of the existing single-descriptor
PDS64 producer: source, DMA control, stride, task lower19 and all CODE16.
Compiled4252d also checks its two additional known DATA fields; copy40355
retains the original unknown masks there. Other unknown DATA stays unclaimed.
Capacity192 does not become CODE or a fetch-length assertion. No instruction
or source producer is replaced or generated by the checker.

The index checker reads only the active little-endian u16 triangle-list range,
checks every index against the declared record count and returns min/max. The
bound is65535 active indices and up to65536 vertex records. It performs no
vertex transform or CPU rendering. Its output is transactional, including a
bad final index. This is an input safety check, not a diagnostic full-buffer
comparison or replacement for a removed framebuffer hash.

## Userspace metadata

`remesa_persistent_scene_vertices_snapshot()` derives exact windows from the
frozen typed TA/PDS/geometry graph, including after public-owner destruction.
The prefix has three active POSITION records48 bytes at offset64, despite its
64-byte capacity. Main draws use tightly packed48-byte records, the original
geometry record count and the actual TA index subwindow. Handles/generations,
active index bytes and committed vertex extents are returned separately.
No provider I/O, allocation, readback, hash or native admission occurs.

## Native validation

A new kernel-only immutable job section binds one index/vertex window per
prefix/draw. It supplies held IDs and scalar ranges/counts, never raw GPU VAs,
register words or CODE. Exact count/size/reserved/alignment checks and disjoint
action/control/USE sections prevent interpreting other metadata as ranges.

`remesa_gem_scene_vertices_check_locked()` runs the existing private-loan,
action/control/USE/actual-TA/state-upload checks under the same endpoint/MMU
locks and private root. It then checks actual PDS bytes and borrowed index
bytes, read-only cached ownership and exact TA index references. Vertex bytes
must equal stride times record count, the PDS source must match the declared
held window, and the whole window must fit its backing. Prefix count stays3.
Overlaps with active indices, PDS or matching USE storage reject.

The task must resolve to a held vertex-master USE entry with committed16 bytes
for prefix or64 for the current compiled profile, not its reserved capacity144.
This check binds that window but does not validate the USE shader body itself.
Caller-provided TA/state scratch is updated during validation; only the final
VERTEX output is transactional. No allocation, default-PD walk, extra flush,
sync/wait, pixel readback/hash or MMIO is added. No capability or incomplete
bit is cleared, and the canonical11 executor stays separate.
