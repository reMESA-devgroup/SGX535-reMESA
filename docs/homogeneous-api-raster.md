# Finite OpenGL raster admission for the native W2 scene

`remesa_context_enable_homogeneous_api_lab` connects the already demonstrated
Mesa API frontend to the newer native scene executor for one explicit recipe:
`REMESA_HOMOGENEOUS_API_W2_CLAMPED`. Enabling the profile does no allocation,
mapping or submission. The resource frontend and native dispatcher must
already be configured. Default screens and contexts retain their previous
refusal, API capabilities and computed version.

The raster descriptor alone does not approve a draw. A pending descriptor may
proceed only with this explicit context profile and the separate compatible
W2 descriptor. Preparation then checks the complete bound recipe before
allocating native parameter/program/geometry owners:

- Exact raw POSITION/NORMAL bytes and coefficient bytes captured from the
  actual Mesa fixed-function API. Their normal-w/alpha lanes are preserved.
- The existing canonical clamped gears vertex semantic and smooth COLOR0
  fragment input, not a caller-supplied replacement shader or fabricated CODE.
- Full viewport at 1280×800 or 640×640, Z24 interval0–1, opaque full-RGBA writes,
  depth LESS/write, queued full COLOR0 black and depth1 cold clears.
- Half-pixel centers, the OpenGL edge convention, both depth clipping flags,
  vertex-color clamp, filled triangles and no culling/scissor. Other global
  raster restrictions remain enforced, including no fragment clamp, depth
  clamp, stipple, polygon offset, multisampling or user clip planes.

The exact input comparisons cover only240 bytes of semantic source data in
this explicit LAB route. They are not framebuffer comparisons or diagnostic
hashes, and add no work to FAST or ordinary rendering. No transformed vertex
or rendered pixel is generated by this admission. The existing GPU vertex
program performs matrix operations, normalization, lighting and COLOR clamp.

## Clip and edge premises

The fixed recipe's clip coordinates are strictly inside all six canonical
planes, with W2 and Z0. Its projected convex hull is inside the existing48×48
footprint at both target sizes. Exact rational verification finds no sample
on a finite triangle edge and135/55 interior half-center samples respectively.
These are the same positions/matrix as the previous physical W2 scene. Filled
triangles with culling disabled make front-face selection immaterial.

`tools/remesa/test_homogeneous_w2_recipe.py` checks those premises against the
sealed old and actual-API input bytes. This offline proof does not establish
generic clipping, universal edge rules or physical execution of CODE344.
The complete new shader/API recipe still requires its own physical run.

## Existing execution and lifetime contracts

The adapter calls the existing homogeneous scene submission path. COLOR, Z
and context share its fence. Definite nonissuance, ambiguous issuance,
retention/quarantine and retirement/publication keep their existing behavior.
A second draw cannot discard the first: it remains refused while attachment
load/preservation is unsupported. Unsupported state and changed recipe inputs
fail explicitly. The kernel independently requires the separate exact LAB
catalogue and all address, ownership, permission, cache and source gates.

The intended native adapter is the separately registered
`remesa_linux_memory_gears_clamped_api_lab_dispatch` for selectors5/6. Enabling
the frontend profile does not configure that adapter or enable any kernel
control. The previous selectors, encoders, actual OpenGL triangle, GLX swap
and restricted continuous GLXGears proofs remain preserved.
