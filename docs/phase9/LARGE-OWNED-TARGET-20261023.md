# Owned 1280×800 color/depth target integration

IMPLEMENTED_OFFLINE. `remesa_persistent_render_target_snapshot` derives a render-target descriptor from a live generic allocation in the existing persistent owner. It resolves owner, generation, handle, GPU VA and allocation extent internally, then applies the existing BGRA8 descriptor encoder to framebuffer dimensions and pitch. Typed depth, shader, geometry, PDS and immutable scene allocations cannot be reinterpreted as color targets. Active CPU leases, insufficient logical backing, dead/foreign owners and quarantined mappings are refused. Output is committed only on success.

The integration fixture allocates 4096000 bytes of color and 4096000 bytes of padded cpp4 Z, then the 4096-byte generated clear/three-draw/close scene on the same endpoint. The existing allocator supplies three disjoint GPU VA intervals; no fixed offsets or sixteen-allocation-limit changes are introduced. The Z prefix is generated from the same owner's actual depth snapshot. Color stride is 5120 bytes. All 1000 color pages are written and read through the existing CPU map/unmap path, checking every byte. This is CPU transport coverage and is not an authenticated native GPU readback.

The provider used by this fixture is injected and refuses dispatch. The production allocator, map/unmap, ownership registry, VA reservation, typed depth allocation and compact scene encoder are exercised. No SSH, MMIO, GPU submission, retirement or new physical result occurred.

The separate native integration remains unqualified: region/scene/DPM and background/event resources must be inventoried; TA/raster setup must consume the 1280×800 scene cookie (region pointer offset 0x10000); the depth prefix replaces existing slots rather than extending the frozen raster list. The previous fixed native ABI captures one 4096-byte color page, whereas this target requires 1000 pages and a separate bounded ownership/response protocol. No existing validator or gate is relaxed by this change.
