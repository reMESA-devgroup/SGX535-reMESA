# Immutable inputs across a general scene session

The general session now seals its GPU READ inputs after the initial admission
has authenticated their contents. This is a prerequisite for reusing a general
driver job without repeated content authentication. It does not admit new
shader bytes or changing application inputs, and does not turn the bounded LAB
endpoint into a production submission interface.

The trusted kernel caller derives the READ mask from the actual prepared
private loan. `remesa_private_session_seal_scene_inputs` checks the same backing
owner, cold-claimed and sealed DPM pools, prepared ticket, exclusive object
holds, generations, initialization, mappings and absence of CPU leases or user
VMAs. It validates the entire set before publishing any seal. The metadata
records the binding count, READ mask and exact IDs in binding order. It does
not read, hash, compare, clear, allocate or flush buffer contents.

The existing `input_seal == 2` mechanism blocks writable CPU leases and writes.
A separate check also refuses user `SYNC` for the recorded general READ IDs;
the older five-input protocol retains its previous behavior. Read-only leases
remain subject to the ordinary job and coherence rules. Topology remains
frozen by the existing backing session. This first contract permits no typed
input updates while the session is active.

Before execution, the general source wrapper derives the READ mask again from
the fresh job's actual private-loan rules. It checks the complete sealed READ
set, binding count, IDs/generations, initialization and exclusive holds. A
changed permission or replacement input cannot inherit the old admission.
DPM retirement, address/permission validation, cache publication and source
attribution retain their existing independent checks.

Source close and complete job/lease retirement must precede backing release.
Release validates all seal metadata and objects before clearing any seal.
File/device loss keeps the owner and seals retained. Failed validation does not
partially unseal the graph or manufacture cleanup/retirement.

The bounded general LAB controller now calls this seal after its initial input
authentication and DPM seal, before canceling admission and claiming the source.
Its existing per-SUBMIT input hashes and separate readback/oracle qualification
remain in LAB. No hashes or diagnostics were added to production FAST, and no
performance gain is claimed from this safety change.
